# WeChat Workbench WeSight 风格 UI 重设计

- 状态：用户已批准
- 日期：2026-08-19
- 适用版本：`0.1.x`
- 参考项目：`reference-project/wesight-obsidian`，固定参考提交 `2315b4be2f4f680419b03fcc0914f1dde622666b`
- 实现方式：clean-room 重写，不复制 WeSight 的 AGPL TypeScript、CSS、图片或品牌资产

## 1. 结论

WeChat Workbench 的右侧工作台将从当前通用后台面板式 UI，重做为 WeSight 公众号预览模块的高保真 clean-room 复刻版。

复刻范围包括信息层级、布局比例、留白、绿色交互体系、双标签导航、主操作栏、单行连接状态和文章预览画布。插件保留 `WeChat Workbench` 名称、自有图标、本地公众号凭据及现有渲染和发布业务层。

首版不引入 WeSight 登录、云账号、积分、订阅或作者托管服务。未登录不是任何功能的前置条件。

## 2. 为什么不复用 WeSight 源码

WeSight 当前参考提交使用 AGPL-3.0-or-later。其公众号主视图约 2434 行，混合登录、云 API、积分、主题生成、文章监控、封面、发布和临时文件等职责；对应公众号视图样式也与 WeSight 全局品牌和状态深度耦合。

直接复用不会降低本项目复杂度，还会使当前 MIT 项目进入 AGPL 衍生作品的许可证路径。因此本次只观察公开界面和交互行为，使用本项目现有接口从零实现。

## 3. 产品边界

### 3.1 保留

- 当前活动 Markdown 笔记的实时预览。
- 内置和 Vault 自定义主题。
- 复制可直接粘贴到公众号编辑器的富文本。
- 本地封面选择、AI 封面生成和明确授权。
- 创建或更新公众号后台草稿、无变化跳过和恢复流程。
- 本地 AppID、AppSecret、Access Token 与图片生成凭据。
- 动作时校验和草稿同步恢复所需的内部业务数据。

### 3.2 不加入

- WeSight 登录页、账号登录限制和云端身份。
- 积分、订阅、付费提示或作者服务。
- WeSight 名称、机器人 Logo、头像素材和品牌文案。
- 文章数据监控标签页。
- 正式群发或公开发布。

### 3.3 文案语义

主按钮使用与参考界面一致的短文案 `发文章`，但其实际行为只同步到公众号后台草稿箱。确认弹窗必须明确写出“同步到草稿箱，不会群发或公开发布”，防止短按钮文案造成误解。

## 4. 页面结构

右侧 `ItemView` 固定采用以下层级：

```text
┌────────────────────────────────────┐
│ [自有图标] WeChat Workbench    [账号] │
├────────────────────────────────────┤
│ 文章预览                   发布设置 │
├────────────────────────────────────┤
│ [发文章] [复制] [主题 · 苍绿⌄]         │
├────────────────────────────────────┤
│ ● 已连接 · 当前笔记                   │
├────────────────────────────────────┤
│                                    │
│      灰色预览背景                   │
│   ┌──────────────────────────┐     │
│   │ 白色文章画布             │     │
│   │ 微信文章排版             │     │
│   └──────────────────────────┘     │
│                                    │
└────────────────────────────────────┘
```

视图继续遵循 Obsidian `ItemView` 规则，可移动、缩放、关闭和恢复，不接管编辑器或主窗口。

## 5. 头部与导航

### 5.1 品牌头部

- 左侧显示自有小图标和 `WeChat Workbench`。
- 右侧只显示圆形账号入口，不直接展示账号哈希、AppID 尾号或“已配置”等技术状态。
- 点击账号入口打开一个基于 Obsidian 官方 `Modal`/`Setting` API 的本地账号快捷面板；完整设置仍通过官方 `PluginSettingTab` 管理，没有登录流程。
- 账号缺失、IP 白名单错误或 Token 错误只在用户触发发布时解释，不占用日常预览空间。

### 5.2 双标签

- 第一项固定为 `文章预览`，不展示当前笔记名。
- 第二项为 `发布设置`。
- 激活项使用微信绿色文字和底部细线；非激活项保持 Obsidian 次级文字色。
- 切换标签不重建渲染产物，只切换可见内容。

## 6. 预览页交互

### 6.1 主操作栏

从左到右固定为：

1. `发文章`：绿色主按钮，打开草稿同步确认弹窗。
2. `复制`：复制可直接粘贴到公众号编辑器的富文本。
3. `主题 · <名称>`：带下拉箭头的宽按钮，打开主题菜单。

4 个内置主题使用固定中文展示名：`编辑精选`、`原生简约`、`技术文档`、`苍绿`。主题 ID 保持 `editorial`、`native`、`technical`、`verdant`，不影响已有文章设置；Vault 自定义主题继续显示其清单中的名称。

`文章封面`移入 `发布设置`。主界面不提供 `复制 HTML 源码`、`重新检查`、`解除草稿关联`或更多菜单；这些技术/恢复操作不属于首版高频路径。

主操作栏只在 `公众号预览` 标签页显示。切换到 `发布设置` 后，同时隐藏主操作栏和连接状态行，让页面只保留可编辑设置内容。

### 6.2 连接状态行

- 左侧为绿色圆点和 `已连接 · <当前笔记名>`。
- 不展示 `需处理`、检查数量、诊断代码或内部预检状态。
- 发布校验仍在用户点击 `发文章` 时执行；如果存在真正阻断项，只提示当前动作需要修复的具体字段，不占用日常预览空间。

### 6.3 文章预览

- 预览区域使用浅灰背景，文章放在居中的白色画布中。
- 画布采用轻边框和轻阴影，不使用明显的大圆角卡片效果。
- 文章内容保持微信公众号宽度观感，图片宽度受画布约束。
- 工具栏和状态行固定在预览滚动区域之外；只有文章画布纵向滚动。
- 被动预览仍不请求远程图片，远程资源使用与正文融合的低干扰占位，而不是技术警告卡片。

## 7. 主题菜单

- 主题控件从原生 `<select>` 改为按钮和 Obsidian 菜单。
- 菜单显示内置主题和已通过校验的 Vault 自定义主题。
- 当前主题带勾选状态；切换后保持原按钮位置，不产生布局跳动。
- 主题加载或渲染期间只在控件内显示加载状态，避免整栏禁用闪烁。
- 主题无法使用时给出简短中文提示；其他可用主题仍能继续选择。

## 8. 发布设置页

发布设置采用 WeSight 式分区页面，不显示内部对象、哈希或原始业务状态。

### 8.1 文章信息

- 标题、作者、摘要和原文链接。
- 四个字段在页面内直接编辑，并通过明确的保存按钮写回当前笔记 Frontmatter。
- 保存后重建同一篇文章的预览；空值删除对应 Frontmatter 字段，使全局默认值或文件名回退重新生效。
- 保存动作必须绑定打开设置页时的当前笔记，切换笔记后旧表单不得写入新笔记。

### 8.2 文章封面

- 展示当前封面缩略图、来源和 `更换封面` 操作。
- 点击后复用现有封面选择器和 AI 生成授权弹窗。
- 没有封面时显示简洁空状态，不显示内部路径或资源哈希。

### 8.3 发布状态

- 展示草稿是否已关联、最近同步结果和是否存在未同步修改。
- 只展示用户能理解的草稿关联与同步结果；需要人工核对时在同步结果弹窗中给出明确下一步。
- 不在页面直接展示 taskId、contentHash、mediaId 等内部字段。

## 9. 空状态、加载和错误

- 无活动 Markdown：保留完整头部和标签，正文显示 `打开一篇 Markdown 笔记开始预览`。
- 渲染中：保留上一份稳定预览，在连接状态行显示轻量加载，不清空画布。
- 渲染失败：画布显示简短错误；用户修改笔记后自动重建，也可重新打开工作台触发重建。
- 复制失败：使用 Obsidian Notice 给出简短原因，按钮恢复可用。
- 发布凭据缺失：点击 `发文章` 后说明需要配置本地公众号凭据，并提供打开设置入口；不限制预览、主题或复制。
- 发布阻断：点击主按钮时用简短中文说明需要补充的文章、账号或封面信息，不发起网络请求。
- 网络或微信 API 失败：继续使用现有发布报告和恢复语义，不在预览页铺开技术堆栈。
- 动作层必须保留首个稳定诊断码，UI 只把它翻译成用户可执行的中文提示，不显示英文原始错误。
- 账号关联不一致时，只在用户触发发布后提供上下文恢复；解除操作必须绑定当时的笔记、`draftId` 与账号标识，并在写入 Frontmatter 的同一原子操作中确认关联未变化。
- 只有本地账号未配置才引导打开设置；尚未产生远端副作用的短暂 Token 网络失败提供安全重试。

## 10. 代码边界

重设计只替换 UI 外壳，不重写已验证业务服务。

- `workbench-view.ts`：组装页面、管理可见状态和转发用户操作。
- 小型 UI 辅助模块分别负责主题菜单、发布设置、封面和同步结果；每个模块只负责一种交互。
- `workbench-controller.ts`：继续提供渲染、复制、主题、封面和发布命令。
- `PreflightReport` 保留为发布/复制动作的内部校验数据，不直接渲染到主界面。
- `styles.css`：使用新的 `wechat-workbench-*` 外壳样式；文章主题继续隔离。
- 渲染、主题、剪贴板、封面、微信 API、发布事务和 SecretStorage 模块不因 UI 复刻而改变契约。

任何新增 UI 状态都必须从现有领域状态派生，不另建与发布状态冲突的持久化副本。

## 11. 响应式与无障碍

- 参考目标为约 520–720px 的右侧面板宽度。
- 窄于 420px 时操作栏允许收缩，主按钮、复制和主题保持可达。
- 标签和按钮提供正确的 `role`、`aria-selected`、`aria-expanded` 与 `aria-label`。
- 所有菜单支持键盘打开、方向键导航、Enter 选择和 Escape 关闭。
- 颜色之外必须有文字或图标表达检查结果。
- 使用 Obsidian CSS 变量适配浅色与深色模式；文章白色画布保持公众号预览语义。

## 12. 验收标准

### 12.1 结构与视觉

- 顶部默认只出现自有品牌和账号入口，不出现账号哈希或技术配置摘要。
- 标签、预览页工具栏、连接状态行和预览画布的顺序与 WeSight 参考界面一致。
- 主操作栏只有 `发文章`、`复制`和主题，且仅在预览页显示。
- 主界面不显示预检结论、警告数量、内部诊断或更多菜单。
- 发布设置页可编辑标题、作者、摘要和原文链接，不显示预览页工具栏与连接状态行。
- 文章封面只出现在发布设置或封面弹窗中。
- 在 520px、640px 和 720px 宽度下无横向溢出、遮挡或不可点击控件。

### 12.2 行为

- 当前文章切换后，标签名、连接状态和预览同步更新。
- 主题切换保持可用并更新预览。
- 复制、封面和发布仍调用原有业务接口。
- 文章渲染完成后，`复制`和`发文章`保持可点击；复制/发布各自在动作时执行必要校验并给出具体反馈。
- 未配置凭据时仍可预览与复制，只有发布动作引导配置。
- 主按钮确认弹窗明确“只同步草稿箱，不会群发”。

### 12.3 验证

- 为新 DOM 结构、精简信息、标签切换、主题菜单和发布设置补充失败测试后再实现。
- 更新窄面板视觉契约测试。
- 运行单元测试、集成测试、类型检查、lint、构建、敏感信息扫描和发布资产校验。
- 同步到隔离测试 Vault，在真实 Obsidian 中验证 520–720px 右侧布局。
- 实机截图必须同时包含中央 Markdown 编辑器和右侧工作台，并与用户提供的 WeSight 参考图逐项核对。

## 13. 明确不改变的事实

- 插件仍名为 `WeChat Workbench`，ID 仍为 `wechat-workbench`。
- 项目仍使用 MIT 许可证。
- AppID、AppSecret 和 Access Token 仍只在用户本机维护。
- 插件仍只创建或更新公众号草稿，不执行正式群发。
- 本次只重做界面与交互外壳，不降低发布事务、安全和隐私约束。
