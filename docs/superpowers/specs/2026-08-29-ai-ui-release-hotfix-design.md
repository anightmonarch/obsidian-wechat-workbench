# AI 生成、候选布局与发布版本一致性热修设计

- 日期：2026-08-29
- 目标版本：`0.1.1`
- 状态：已按用户当前指令批准实施
- 范围：AI 标题、摘要候选、智能封面配置反馈、样式面板打开状态与 GitHub Release 资产一致性

## 1. 已确认事实

1. Git 历史和 reflog 没有 `reset`、`rebase` 或回退记录；本地 `main` 比公开 `origin/main` 多一个封面错误分类提交。
2. 当前源码构建、公开 `0.1.0` Release 和 `commit_note` Vault 中的 `main.js` 哈希互不相同，但都声明版本 `0.1.0`。问题是同版本多构建串线，不是源码回退。
3. 官方 `obsidianmd/obsidian-releases` 的 `community-plugins.json` 当前没有 `wechat-workbench`，也没有对应提交 PR。GitHub 仓库和 Release 已公开，但尚无证据证明已被官方社区插件目录收录。
4. 当前样式面板源码已经包含主题、字体、字号、主题色、标题、代码主题、图注与开关。截图展示的是面板下半段，不作为源码回退证据。

## 2. 配置缺失反馈

- 标题、摘要和封面继续使用各自独立的服务配置。
- 用户点击“智能生成”时，如果当前图片供应商、模型或 API Key 不完整，不打开生成弹窗。
- 封面区域原位展开与标题、摘要候选区同级的提示：`图片服务未配置完整，请到插件设置检查`。
- 提示不得包含 API Key、SecretStorage 键名、Endpoint、原始异常或内部错误对象。
- 配置完整时保持现有隐私确认弹窗和生成流程。

## 3. 标题响应兼容边界

标题结果仍必须满足：

- 恰好 3 个候选；
- 每个候选清洗后非空且最多 64 个 Unicode 字符；
- 三个候选互不重复；
- 不自动覆盖当前标题。

解析器按下列顺序接受供应商输出：

1. `{"titles":[...]}` JSON 对象；
2. 仅包含三个字符串的 JSON 数组；
3. 三行纯文本；
4. 使用 `1.`、`2.`、`3.`、`1、` 或项目符号开头的三行列表。

包含解释段落、候选数量不是 3、重复、空值或超出既定结构的结果仍返回 `AI_TEXT_PROVIDER_OUTPUT_INVALID`。摘要既有 JSON/单段纯文本边界不变。

## 4. 摘要候选自适应布局

- 候选区和候选按钮不得设置固定高度。
- 按钮使用 `height: auto`、`white-space: normal`、`overflow-wrap: anywhere`，并允许容器随 1–120 字内容自然增高。
- 文本不得溢出灰色候选背景，不得被裁剪，不新增内部滚动条。
- 标题候选共享同一规则。

## 5. 样式面板版本判定

- 样式面板新建时将滚动位置置顶，确保首先展示主题、字体、字号和主题色。
- 面板已打开期间，修改样式和普通渲染刷新继续保持滚动位置，遵守既有“更新不闪烁、不重置滚动”的规则。
- 不删除现有代码主题、图注和六个开关；不以截图下半段为由回退样式能力。

## 6. 发布一致性

- 新版本固定为 `0.1.1`，同步更新 `manifest.json`、`package.json`、`package-lock.json` 和 `versions.json`。
- Release tag 必须精确为 `0.1.1`，不带 `v`。
- `main.js`、`manifest.json`、`styles.css` 必须来自同一次通过门禁的构建，发布前后分别记录 SHA-256 并逐一相等。
- 禁止继续替换 `0.1.0` 的既有资产。
- GitHub Release 成功与官方社区插件目录收录分开报告。只有 `community-plugins.json` 存在插件条目后，才能声称 Obsidian 社区插件用户可自动发现更新。

## 7. 验收

- 单元测试覆盖缺配置封面提示、四种标题格式、拒绝宽松错误输入、多行候选 CSS 和样式面板新开置顶。
- 全量执行 typecheck、lint、测试、构建、Release 校验、依赖审计与敏感信息扫描。
- 只在 `wechat-workbench-test-vault` 构建同步并重载 Obsidian，验证四条真实用户路径。
- AI 在线调用只使用隔离 Vault 的 SecretStorage；验证记录不保存 Key、完整响应或生成图片 URL。
- 发布后核对 GitHub tag、Release 状态、三个资产名称和哈希；再独立核对官方社区插件目录状态。
